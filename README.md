# HPC 集群监控面板（SLURM Monitor）

基于 **Node.js + SSH** 的 Slurm 算力集群网页监控工具。通过 SSH 连接集群登录节点，实时展示节点、分区、任务、存储等状态。无需在集群上安装任何组件，浏览器打开即用。

## 功能特性

- **集群总览** — CPU / 内存总量与使用率、节点状态分布（空闲 / 混合 / 满载 / 离线）
- **分区监控** — 各 Slurm 分区的节点分配、空闲数量与使用率
- **节点详情** — 点击节点卡片查看 CPU / 内存 / GPU / 系统信息 / 拓扑
- **我的任务** — 当前用户任务的运行状态、排队原因、GPU 分配等
- **存储使用** — 集群挂载点容量、登录节点内存、用户家目录用量
- **自动刷新** — 每 30 秒静默刷新，数据无变化时不打扰；支持手动刷新
- **安全设计** — 密码仅存内存、Bearer 令牌鉴权、接口限流、默认仅监听本机

## 环境要求

- **Node.js ≥ 18**（推荐 LTS 版本）
- Windows（可使用一键启动脚本）或任意可运行 Node.js 的系统（手动启动）
- 可正常 SSH 登录的 Slurm 集群登录节点

## 准备工作：安装 Node.js

如果电脑尚未安装 Node.js，请按以下步骤操作：

1. 打开浏览器访问 **https://nodejs.org**
2. 点击绿色的 **LTS**（长期支持版）按钮下载 Windows 安装包（`.msi` 文件）
3. 双击安装包，一路点 **Next**（下一步），保持默认选项即可（安装程序会自动勾选「Add to PATH」）
4. 点击 **Finish** 完成安装

验证安装：打开命令提示符，执行 `node --version`（显示 `v18.x.x` 或更高）和 `npm --version`（显示 `v9.x.x` 或更高）。

> 💡 如果提示「不是内部或外部命令」，请重启电脑后再试。

## 快速开始

### 方式一：Windows 一键启动

双击 **BioAgent.vbs**，脚本会自动完成：

1. 检查 Node.js 是否已安装
2. 首次运行自动执行 `npm install`（耗时约 1-2 分钟）
3. 启动后端服务并**检测端口 3000 是否就绪**（被占用会弹出提示，不会静默失败）
4. 自动打开浏览器进入监控页面

### 方式二：手动启动（任意系统）

```bash
npm install
npm start
```

启动后访问 **http://localhost:3000/cluster.html**。

可用环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3000` | 监听端口 |
| `HOST` | `127.0.0.1` | 监听地址；设为 `0.0.0.0` 可允许局域网访问（建议配合 `SETUP_TOKEN`） |
| `SETUP_TOKEN` | 无 | 首次初始化口令；设置后首次登录必须提供，防止局域网内被抢先接管配置 |

## 登录使用

首次打开会看到登录弹窗：

```
┌──────────────────────────────────────────┐
│              HPC 集群监控                │
│              Slurm 算力集群              │
│                                          │
│  👤 用户名                               │
│  ┌──────────────────────────────────┐    │
│  │ 请输入您的用户名                  │    │
│  └──────────────────────────────────┘    │
│  ──────────────────────────────────────  │
│  🖥  Slurm 集群连接                      │
│  集群地址   ┌──────────────────────┐     │
│             │ 主机名或 IP           │     │
│             └──────────────────────┘     │
│  端口  ┌────────┐  SSH 用户 ┌────────┐  │
│        │ 22     │          │ 用户    │  │
│        └────────┘          └────────┘  │
│  SSH 密码 ┌──────────────────────┐     │
│           │ ······               │     │
│           └──────────────────────┘     │
│                                          │
│  [🔌 测试连接]         [🚪 进入监控]    │
│                                          │
│  💡 首次使用请填写集群信息并「测试连接」  │
└──────────────────────────────────────────┘
```

**使用步骤**：

1. 输入**用户名**（平台显示名，用于识别身份；登录时还可自定义「服务器命名」）
2. 填写 **Slurm 集群连接信息**：集群地址（主机名或 IP）、端口（默认 22）、SSH 用户名、SSH 密码
3. 点击 **「测试连接」** 验证 SSH 连接是否正常（仅验证，不修改配置、不登录）
4. 确认成功后点击 **「进入监控」**

> 💡 SSH 密码只保存在服务器内存中，**不写入任何磁盘文件**。关闭浏览器或重启后端后需要重新登录。
> 首次登录会把集群地址、端口、SSH 用户名等非敏感信息保存到 `cluster.config.json`，下次打开登录框会自动填充。

### 修改配置

点击顶部导航栏的 **⚙ 设置** 按钮或连接状态区域，即可重新打开登录界面修改集群连接。

## 监控面板功能

### 顶部导航栏

| 元素 | 说明 |
|---|---|
| 品牌标题 | 显示集群名称（登录时的「服务器命名」） |
| 连接状态 | 🟢 在线 / 🔴 离线 / 🟡 加载中，点击可修改配置 |
| ⚙ 设置 | 打开登录层修改集群连接 |
| 🔄 刷新 | 立即手动刷新（会显示加载中） |
| 用户头像 ▾ | 展开下拉菜单 |

### 用户下拉菜单

| 项目 | 说明 | 数据来源 |
|---|---|---|
| 运行程序 | 当前运行数 / 总数（含排队） | `squeue` |
| 可用 CPU | 账户配额可用 CPU 核数 | `sacctmgr assoc` (GrpCPUs) |
| 可用内存 | 账户配额可用内存 | `sacctmgr assoc` (GrpMem) |
| 退出登录 | 清除登录态，回到登录页面 | — |

### 摘要卡片

- **CPU 总量** — 集群总核数、已分配 / 空闲核数、使用率进度条
- **内存总量** — 集群总内存、已分配 / 空闲、使用率进度条
- **节点分布** — 总节点数及各状态数量（空闲 / 混合 / 满载 / 离线）
- **我的任务** — 当前用户运行中 + 排队中的任务数

### 存储使用

- 集群各挂载点：文件系统、总容量、已用、可用、使用率（🟢 < 60% / 🟡 60-80% / 🔴 > 80%）
- 当前节点内存：登录节点 `free -h` 实时输出
- 用户家目录：`du -sh` 统计（独立请求，不阻塞其他数据刷新）

### 分区

所有 Slurm 分区列表：分区名称、已分配 / 总节点、空闲节点数、使用率进度条。

### 节点

每个计算节点的卡片展示：状态标签（空闲 / 混合 / 满载 / 离线）、CPU 分配与负载、内存分配与可用、GPU、归属分区。
**点击节点卡片**可查看详情弹窗：系统架构、操作系统、节点地址/主机名、CPU 拓扑等。

### 我的任务

当前用户在集群中的所有任务表格：

| 列 | 说明 |
|---|---|
| JOBID | 任务编号 |
| 分区 / 名称 | 所在分区与任务名 |
| 状态 | 🟢 运行中 / 🟡 排队中 / 🔵 完成中 / 🔵 已完成 / 🔴 失败 / ⚪ 已取消 |
| 运行时间 / 节点 | 已运行时长与分配节点数 |
| GPU | 任务申请的 GPU 资源（老版本 Slurm 不支持 `%b` 时自动降级） |
| 排队原因 | 未运行任务的排队原因 |

## 自动刷新

面板每 **30 秒** 自动刷新一次。数据无变化时页面保持安静（不重播动画、不闪「加载中」）；点击 **「刷新」** 按钮手动刷新时才会显示加载状态。用户家目录统计（`du -sh`）为独立请求，不会阻塞其他监控数据的刷新。

## 安全说明

### 密码保护

SSH 密码**只保存在服务器内存中，从不写入磁盘**：

| 要素 | 说明 |
|---|---|
| 密码落盘 | 从不写入 `cluster.config.json` 或日志文件 |
| 登录验证 | 输入账号密码后，后端先实际测试 SSH 连接，验证成功才签发会话令牌 |
| 会话令牌 | 随机 32 字节令牌，仅保存在当前浏览器标签页（sessionStorage），12 小时滑动过期 |
| 重新登录 | 关闭浏览器或重启后端后，需重新输入 SSH 账号密码 |

`cluster.config.json` 中只保存集群地址、端口、SSH 用户名等非敏感信息，即使被意外查看也没有密码泄露风险。

### 网络防护

- 后端默认只监听本机回环地址 `127.0.0.1`，局域网内其他设备无法访问
- 如需局域网访问，可设置环境变量 `HOST=0.0.0.0` 后启动（所有接口仍需登录令牌，但建议仅在可信网络使用）
- **首次初始化口令**：监听非回环地址时，建议同时设置环境变量 `SETUP_TOKEN=<随机口令>`，防止局域网内其他人抢先接管配置
- **测试连接不会登录**：只验证 SSH 凭据，不修改配置、不签发登录令牌
- 除健康检查、登录和测试连接接口外，所有 API 均需携带登录后签发的 `Authorization: Bearer <token>` 请求头
- 登录与「测试连接」接口带内存限流（每 IP 每分钟最多 8 次尝试），降低暴力尝试 SSH 口令的风险
- 页面与 API 响应均带 `Cache-Control: no-store`，避免浏览器缓存旧数据
- 已移除存在任意命令执行风险的 `/api/slurm/exec` 接口

## 故障排除

### 后端未启动

```
❌ 后端服务未运行
```

- 双击 `BioAgent.vbs` 启动；如果弹出「后端未能正常启动」提示，通常是**端口 3000 已被其他程序占用**，关闭占用程序后重试
- 手动排查：在项目目录执行 `npm start`，查看命令行中的报错信息

### 连接失败

```
❌ SSH 连接失败
```

- 检查集群 IP / 端口是否正确
- 确认 SSH 用户名和密码无误
- 检查集群是否开放 SSH 端口（默认 22）
- 确认网络连通性

### 提示重新登录

- 关闭浏览器或重启后端后，会话令牌失效，重新输入 SSH 账号密码即可
- 多标签页场景：用**相同的集群凭据**可直接重新登录；如需**更换为不同的集群**，请先在其他已登录的标签页退出登录

### 页面显示异常

- 按 **Ctrl + F5** 强制刷新（页面禁止缓存）
- 点击「刷新」按钮强制拉取数据
- 关闭浏览器重新打开

## 技术栈

| 组件 | 技术 |
|---|---|
| 前端 | 原生 HTML5 + CSS3 + JavaScript（单文件，无构建步骤） |
| 后端 | Node.js + Express |
| 集群通信 | SSH2（ssh2 npm 包） |
| 认证 | 登录后签发随机会话令牌（Bearer Token，12 小时滑动过期） |
| 安全 | 登录/测试接口限流、默认仅监听回环、可选 SETUP_TOKEN |
| 端口 | 3000 |
